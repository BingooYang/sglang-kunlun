
> # 🔴 先读这一条：不要 `kill -9` 卡在 XPU 调用里的进程
>
> **2026-10-17 踩的最惨的坑。** 对"卡在 XPU 调用里"的进程（CPU 100% 空转、
> GPU `0% util`、显存不涨）执行 `kill -9`，会在设备上留下**杀不掉的 kernel**
> （`xpu-smi` 显示 `util=100%` 但 `Processes: None`），拖坏整个 XPU runtime ——
> 之后连 `torch.ones(1024, device='cuda')` + `sync` 都会间歇性挂死。
> 更糟的是驱动会**泄漏 "in use" 引用计数**，此后 `xpu-smi -r`（逐卡 HW reset，
> 官方唯一的用户态恢复手段）对**全部 8 张卡**都报
> `XPU ... is currently in use by another process` —— **即使没有任何进程持有
> `/dev/xpu0..7` / `/dev/xpuctrl`**（逐 `/proc/*/fd` 扫过）。结果：**只能节点级重启**。
>
> **正确做法**：① 卡死先**等**（XPU 调用自带超时），别条件反射地杀；② 必须杀时，
> 杀完确认 **8 张卡都回到 `0 MiB / 0%`** 再起下一个任务；③ 服务挂了不要立刻重试，
> 先看 `xpu-smi` 是否全绿；④ 脚本里的 `pkill -9` 清理逻辑**是有代价的**，别当常规手段。
>
> 完整时间线 / 最小复现 / 恢复步骤见 **`examples/eb/README.md`** 第 4、5 节。

## 文档没写、但踩到的三个坑

1. **`libpython3.so` / `libpython3.10.so.1.0` 缺失（最关键）**
   本机基础 CPython 3.10 是**静态编译**的（`sysconfig` 里 `Py_ENABLE_SHARED=0`，
   `/usr/local/lib` 只有 `libpython3.10.a`），所以既没有 `libpython3.so`，
   也没有 `libpython3.10.so.1.0`。而 xpytorch 导入钩子要 `CDLL("libpython3.so")` 探活，
   `torch_xmlir` 的 7 个扩展 .so 还直接 `DT_NEEDED libpython3.10.so.1.0` —— 两者都会失败，
   结果是导入钩子静默报 WARNING、XPU 运行时根本没初始化、`device_count()` 恒为 0。
   解法：`env/klx_stub/` 放两个**空实现占位库**（源码 `tool/libpython3.c`，
   用 `tool/build_libpython3_stub.sh` 生成，注释里有完整说明）。
   因为解释器是 `-rdynamic` 链接的、已经把 ~900 个 `Py*` 符号导出到全局作用域，
   占位库只要能让 `dlopen` 成功，真正的符号由主程序解析。由 `tool/env.sh` 挂进 `LD_LIBRARY_PATH`。

2. **`hyperparameter` 版本**：xpytorch 要 `from hyperparameter import param_scope`，
   而 PyPI 默认装的 0.6.0 已把 `param_scope` 改名成 `scope`。必须 `==0.5.12`
   （0.5.3~0.5.12 有 `param_scope`；0.5.0~0.5.2 是 manylinux_2_34 轮子，
   本机 glibc 2.31 装不上）。

3. **torch 版本护栏**：sglang 的 pyproject 声明 `torch==2.13.0`，装它的依赖时
   （实测是 `torchvision`）会把 torch 升到 2.14.1，整套昆仑运行时随之失效。
   用 `pkg/constraints.txt` 锁 `torch==2.9.0 / torchvision==0.24.0 / triton==3.5.0`。
