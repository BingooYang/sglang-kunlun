# 1. 下载权重

> 🔴 **起服务/跑压测前必读**：不要对"卡在 XPU 调用里"的进程 `kill -9` —— 会在设备上留下
> 杀不掉的 kernel，拖坏整个 XPU runtime，并让 `xpu-smi -r` 也无法恢复（只能节点级重启）。
> 详见 **`doc/2. 构建环境.md` 顶部** 与 **`doc/3. eb5模型运行.md` 的「最重要的一条」**。

把 H 卡机器上的 `hf_checkpoint-48800`（12295 个文件 / 534 GB）拉到本机。

## 1. H 卡机器（10.95.239.155）起服务

```bash
cd /root/paddlejob/inference-public/fanxiangyu/models/ernie_lite_layer43_mla_hca_dsa_midtrain_1001/hf_checkpoint-48800
python -m http.server 1024 --allowedip 10.79.130.26   # 白名单 = 本机 IP
```

## 2. 本机下载

```bash
BASE=http://10.95.239.155:1024/hf_checkpoint-48800
DEST=/root/paddlejob/workspace/bingoo/models/hf_checkpoint-48800
mkdir -p "$DEST" && cd "$DEST"

curl -s "$BASE/" | grep -o 'href="[^"]*"' | sed 's/href="//;s/"//' | grep -v '^/' | sort -u > /tmp/files.txt
export BASE
cat /tmp/files.txt | xargs -P8 -I{} bash -c '
  [ -s "$1" ] && exit 0
  curl -sS -f --retry 5 -o "$1.part" "$BASE/$1" && mv -f "$1.part" "$1"' _ {}
```

约 25 分钟（8 并发 ~1.1 GB/s）。已存在的文件会跳过，中断可直接重跑。

## 3. 校验

```bash
find "$DEST" -maxdepth 1 -type f | wc -l          # 期望 12295
find "$DEST" -maxdepth 1 -name '*.part' | wc -l   # 期望 0
```

## 注意

> 📌 **2026-10-17 补**：白名单是**按本机当时的 IP** 配的。容器重建后本机 IP 会变
> （本次从 `10.79.130.26` 变成 `10.129.9.7`），症状是**只返回 403、不是连不通**
> （`ping`/22/80/443 本来就不通，只有 1024 通，属正常）。此时**别去排查网络**：
> 直接 `hostname -I` 拿到本机 IP 报给 H 机器那侧，请它重起
> `python -m http.server 1024 --allowedip <新IP>` 即可。
>
> 本次重建实测：12295 个文件 / 534 GB，8 并发约 12 分钟下完；
> 与服务端清单逐名对比**无缺失、无多余、无 0 字节文件**。

- 返回 **403** = 白名单没配对；先 `curl -s -o /dev/null -w "%{http_code}" "$BASE/"` 确认是 200。
- 该机 ping 不通、22/80/443 等全不通，**只有 1024 通**，属正常。
- **不支持 Range 请求，无断点续传**，单个分片断了只能整片重下。
