# 4. 临时 D2H 与性能债（EB5 on 昆仑）

> 建立于 2026-10-20。**策略：先打通功能，允许小 metadata 临时 `.cpu()`；逐条登记，后续挪回 XPU。**
> 主文档见 `3. eb5模型运行.md` §12；等适配收敛后本节会合并进 §12.7。
> 8L 适配过程中所有问题的**分类索引**见 `5. EB5 8L 问题归类与修复索引.md`。

## 规则

1. **大张量（KV / hidden / logits）禁止整块 D2H**：会直接挂死或 OOM（`flash_mla_sparse_fwd`
   的 `kvs.float()` 曾要 42.5 GiB）。
2. 小 metadata 允许临时 `.cpu()`，但必须：
   - 代码里写 `# PERF-TODO(eb5): <原因 + 计划>`；
   - 在下表登记一行。
3. 优化顺序：
   - ① 能留在设备上的绝不回读；
   - ② 必须回读的用异步拷贝 + 事件对齐，避免每 step 同步；
   - ③ 分支条件优先用 host 侧已有的量（`numel()`、预计算的 CPU 副本）。

## 二、Kernel 契约对齐（dtype / 形参 / 符号名）

这类问题不是性能债，但高频、易误判，统一记录。

### 2.1 原则

1. **字节容器的 dtype 差异用 `view` 重解释，不做数值转换**：
   `uint8` ↔ `int8`、`float8_e4m3` ↔ `uint8` 都是同宽（1 字节），
   `tensor.view(torch.int8)` 是**零拷贝、零精度损失**的位模式重解释。
2. 只有当代码要对容器做**数值运算**时，才需要关心有符号/无符号（fp8 数据本身按 E4M3
   位模式解释，与容器是 int8 还是 uint8 无关）。
3. 形参差异（多一个位置参数、少一个 kwarg）用**显式形参 + 断言**处理，
   不要用 `**kwargs` 静默吞掉有语义的参数。

### 2.2 已遇到的案例

| 案例 | 现象 | 处理 | 精度影响 |
|---|---|---|---|
| `gather_paged_scale` 的 `kv_cache` | `RuntimeError: dtype of kv_cache (Byte) must be one of [Char]`（2026-10-20 22:24，`nsa_indexer.py:619`） | 传入前 `buf.view(torch.int8)` | **无**：纯位模式重解释，FP8 字节语义不变 |
| `set_mla_kv_buffer_kernel` 位置参数 | `takes 9 positional but 10 given`（fork 新增 `reserved_skip_index`） | 补形参 + `assert reserved_skip_index == 0` | 无 |
| `set_mla_kv_buffer` 的 dtype | kernel 要求 `seq_lens` int64 / `last_loc` int32，XPU 侧 int64→int32 不可靠 | 插件里经 CPU 往返转换 | **有 D2H 开销**（已在第一节登记）；数值无损失 |
| `Indexer._get_topk_ragged_with_cp` / `is_nsa_prefill_cp_in_seq_split` | fork 已删除/改名 | 显式守卫 + 明确报错 | 无 |
| `@register_triton_op("模块路径", ...)` | 模块路径不存在 → 注册静默失效 → `[grid]` 报错 | 用 `find_spec` 静态校验 | 无 |

### 2.3 判断"是否有精度风险"的快速准则

- **只在字节层面搬移 / gather / scatter / 传给 kernel** → `view` 即可，**无精度风险**；
- **要对值做算术** → 必须确认 kernel 期望的容器语义（signed/unsigned、fp8/fp16），
  必要时显式 `.to(dtype)`；
- **fp8 量化数据** → 位模式即语义，`int8`/`uint8` 容器不改变解码结果。
