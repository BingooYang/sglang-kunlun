## 二、A. 设备 / 环境类

### A1. 半坏设备："任何 device op 都挂"
- **现象**：`xpu-smi` 显示 `0MiB / 0%`、无进程，但 `torch.tensor(..., device="cuda")`、
  `.cpu()`、`.item()` 永久挂住；dmesg 有 `KL_XID_KERNEL_EXCEPTION`
- **根因**：挂死/崩溃收尾会留 Xid；之后设备进入"通信能通、算力不能用"的半坏态
- **修法**：`xpu-smi -fr -i <卡>`（**强制** reset）。顺序必须是"先 py-spy 取栈，再 reset"，
  否则丢失现场
- **已验证**：0–3、4–7 都成功恢复；`-fr` 后约 30 s 内新进程可能报
  `invalid device ordinal`，属瞬时态
- **反例**：非强制 `xpu-smi -r` 会被"in use"挡住；老文档"只能节点重启"已过时

### A2. 卡号映射：可见序号 4–7 与 xpu-smi 交叉
| 可见序号 | `/dev/xpuN` | `xpu-smi` 卡号 |
|---|---|---|
| 0–3 | 0–3 | 0–3 |
| 4 | xpu5 | 5 |
| 5 | xpu4 | 4 |
| 6 | xpu7 | 7 |
| 7 | xpu6 | 6 |

- **原因**：`tool/env.sh` 的 `CUDA_DEVICE_ORDER=OAM_ID`
- **影响**：按可见序号单卡 `-fr` 会复位错卡；按集合（`-i 4,5,6,7`）不受影响

### A3. 端口残留（`dist_init_port`）
- **现象**：`ValueError: dist_init_port at 30321 is not available in 30 seconds`
- **根因**：上一轮 launcher 未退，仍 LISTEN
- **映射**：`ZMQ_TCP_PORT_DELTA = 233`（`server_args.py:812`），即
  `dist_init_port = http_port + 233`（30088 → 30321，**不是 30322**）
- **修法**：`stop_kunlun.sh` 清残留；或换 http 端口避开被占区间

### A4. `stop_kunlun.sh` 是全局的
- **现象**：一个 agent 起服务时把另一个 agent 的服务当"残留"TERM 掉
- **根因**：脚本按进程名扫描，无 GPU 过滤
- **修法**：多任务并行时，约定"卡集不重叠 + 起服务前手工确认"；脚本已支持
  `STOP_GPUS/EB5_GPUS` 的空闲卡判定，但**终止动作仍是全局**的

### A5. 启动期 gloo 级联失败
- **现象**：`gloo/transport/tcp/pair.cc: Connection reset/closed by peer`
- **根因**：通常是某个 rank 先退出/卡死；gloo 只是受害者。配合 A1 一起看

### A6. 多 rank INT8 起服务卡在加载收尾 / DeepEP buffer 初始化
- **现象**：2 卡卡在 `get_available_gpu_memory → empty_cache`（权重已加载完）；
  4 卡卡在 `deep_ep/buffer_v2.py:101 all_gather_object`（`get_deepep_buffer`）；
  两者都是 N 卡 100% util + CPU 100%，5–6 min 无进展
- **取证**：`py-spy dump --pid <sglang::scheduler_DPx>`（`--nonblocking`；先看 Python 栈再动手）
- **结论**：与 CUDA graph 无关（尚未进到捕获）；**未修**，见 doc/7 §8.4/§8.5
- **附**：同机再起单卡服务时 `--nccl-port 9999` 会 `EADDRINUSE`，需显式换端口

## 三、B. 插件 ↔ fork API 漂移（最多的一类）

| # | 旧 API（插件里） | fork 现状 | 处理方式 | 证据 |
|---|---|---|---|---|
| B1 | `forward_batch.attn_backend` | 已删，改用 `get_attn_backend()`（forward_context） | 改调用点 | `nsa_indexer.py:770` |
| B2 | `nsa_enable_prefill_cp` | 改名 `dsa_enable_prefill_cp` | 双名兼容（`getattr`） | `nsa_indexer._enable_prefill_cp` |
| B3 | `_get_k_bf16(x, forward_batch)` | 签名变 `(x, positions)` | 改签名 + AST 校验调用点 | 兼容用例 |
| B4 | `indexer.wk` / `_fused_k_weights` | EB5 是 fused indexer，只有 `wk_weights_proj` | 投影统一用 `F.linear(权重)` | `_indexer_torch_ref` |
| B5 | `forward_batch.token_to_kv_pool` | 已删；且 EB5 需要 `full_kv_pool` | `_indexer_kv_pool()`：取模块属性 + 解包 | `No indexer pool for compression ratio 128` |
| B6 | `metadata.get_seqlens_int32_cpu()` | 已删，只留 `get_seqlens_int32()` | 优先 `ForwardBatch.seq_lens_cpu`（零 D2H），expanded 才回退 | 22:02 报错 |
| B7 | `metadata.get_nsa_extend_len_cpu()` | 改名 `get_dsa_extend_len_cpu` | 双名兼容 | `_extend_lens_cpu` |
| B8 | `Indexer._get_topk_ragged_with_cp` | 已删 | 删除 hook + 静态防回归 | 启动期 hook 解析失败 |
| B9 | `forward_batch.nsa_cp_metadata` | 已删 | 显式守卫；**每次 prefill 都会读**，不是只有开 CP 才炸 | 真实 bug |
| B10 | `dsa.utils` 缺 5 个 `dsa_cp_*` 符号 | 部分改名/删除 | 等价符号映射 + 纯 torch 补齐 | `_nsa_backend_impl` 可导入 |
| B11 | `dp_attention.get_attention_tp_size` | 已删 | 改 `get_parallel().attn_tp_size` | 否则 import 仍失败 |
| B12 | `@register_triton_op("sglang.srt.mem_cache.triton_ops.allocator", ...)` | 模块路径不存在 | `find_spec` 静态校验；注册改到真实路径或直接替换模块实现 | `alloc_decode_kernel[grid]` |
| B13 | graph replay 路径 `'function' object is not subscriptable` | 插件只替换了**内层** kernel，外层 `fused_dsa_decode_metadata` 仍 `kernel[grid]` | 外层也替换（`kernel_ops.py` 末尾，`EB5_DSA_META_GRAPH_PATCH=1`） | graph replay 必现；eager 不触发（doc/7 §8.3.3） |

**共性教训**：
- 这类问题多为**静默失败**（hook 解析不到只打 warning），必须在启动日志里 grep
  `Failed to apply hooks`；
- 单测里加**静态扫描**（旧符号名、注册模块路径）比逐个碰运气有效。

## 四、C. 算子不可用：Triton / tilelang / deep_gemm / stub

统一原则见 `3. eb5模型运行.md` §12：**kernel 级 torch 化，不打桩、不在调用层绕开。**

| # | 算子 | 报错形态 | torch 化方式 | 验证 |
|---|---|---|---|---|
| C1 | `transform_index_page_table_{prefill,decode}_kernel[grid]` | `'function' object is not subscriptable` | `arange/gather/where` + 页表映射 | 8 组形状 vs ref 逐元素相等 |
| C2 | `_append_indexer_swa_kernel[grid]` | 同上 | 向量化 + 前缀/尾部 gather + `scatter_` | 3 模式 vs ref 相等 |
| C3 | `alloc_decode_kernel[grid]` | 同上 | `cumsum` 前缀 + `index_select` + `where`（分支用 host `numel()`） | 逐行对照 kernel |
| C4 | `sgl_kernel.fast_topk_transform_fused` / `..._ragged_fused` | `NotImplementedError`（stub） | 窗口 topk + page-table 映射 + 右侧补 -1 | 10 组 CPU 用例 |
| C5 | `mhc_post_tilelang` / `mhc_pre_big_fuse_*` / `mhc_pre_gemm_sqrsum_*` / `tf32_hc_prenorm_gemm` | `tilelang`/`deep_gemm` 未安装 | kernel 级 torch 替代（chunk 化 matmul） | `layer/` 158 passed |
| C6 | `set_mla_kv_buffer_kernel` 少第 5 个位置参数 | `takes 9 positional but 10 given` | 补 `reserved_skip_index=0` + 断言 | 服务通过 |
| C7 | `dequant2d_per_token` | `optimized_ops::dequant2d_per_token failed r=2` → `KL_XID_KERNEL_EXCEPTION` / `illegal memory access` | 未修；**ep=2 形态必现（eager 也炸），ep=4 正常** | doc/7 §8.2 |

## 五、D. dtype / 形参契约

| # | 现象 | 根因 | 处理 | 精度风险 |
|---|---|---|---|---|
| D1 | `dtype of kv_cache (Byte) must be one of [Char]` | fork 的 buffer 是 uint8，昆仑 kernel 要 int8 | `buf.view(torch.int8)` | **无**（同位宽位模式重解释） |
| D2 | `torch_lod_cpu_opt->dtype() ... left operand=long int` | kernel 要 int32，拿到 int64 | `.to(torch.int32)`（值是 token 索引，安全） | 无 |
| D3 | `set_mla_kv_buffer` 形参个数 | fork 新增 `reserved_skip_index` | 补形参 + 断言 | 无 |
| D4 | `int64→int32` 的设备侧 cast 不可靠 | XPU 限制 | 插件里经 CPU 往返（**有 D2H**，已登记性能债） | 无 |

## 七、F. 调度 / 并发

### F1. 单请求让 DP 集合通信死锁
- **现象**：`health_generate` 后 4 个 rank 栈不一致（有的在 `broadcast_pyobj`、
  有的在 `all_gather_into_tensor`），最终 gloo 连接重置
- **根因**：请求只落到一个 DP rank；其余 rank 没有 batch，不进入
  `prepare_mlp_sync_batch` 的 all_gather
- **修法（测试侧）**：**不要先打 `health_generate`**；ready 后直接并发 N 个请求；
  探活用 `/health`（不触发前向）
- **修法（代码侧，未做）**：让无 batch 的 rank 也参与同步（发空 batch）

### F2. 相同 prompt 被前缀亲和到同一 rank
- 8 个相同 prompt 全部路由到 DP0 → 其余 rank 空闲 → 同样的死锁
- **修法**：验证时必须用**不同 prompt**

### F3. 并发数 = DP rank 数
- 4 并发时仍可能 3/4（某 rank 分不到活），8 并发更稳；最终成功的一轮用 4 个不同 prompt
